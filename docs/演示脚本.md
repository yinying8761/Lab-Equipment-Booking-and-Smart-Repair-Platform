# 现场演示脚本（6~8 分钟）

> 演示前检查：三个服务已启动（`scripts/start-all.ps1`），数据库已按 `db/init.sql` 初始化，
> 浏览器提前打开 `http://localhost:5173`，两个浏览器窗口分别用于普通用户与管理员（或使用无痕窗口）。
> 建议提前把 `evidence/` 下的截图与报告放在副屏，主链路不故意制造服务故障。

## 0. 开场（30 秒）

"我们做的是实验室设备预约与智能报修平台。业务上是设备台账、预约审核、报修工单三个闭环，
AI 上是带来源引用的知识问答和能真实建单的智能助手。下面按一条完整业务线演示。"

## 1. 设备台账（40 秒，对应 AT-01）

1. 用 `student01 / Student@123` 登录，进入工作台，说明统计卡片来源真实数据库。
2. 进入"设备台账"，用关键词"离心"筛选，打开"详情"抽屉，指出编号、实验室、状态、使用说明。
3. 说明：状态为"停用"的设备不出现预约按钮，避免无效申请。

## 2. 预约闭环（90 秒，对应 AT-02 / AT-03）

1. 选择一台可用设备，点击"预约"，选择明天的一个 1 小时时段（系统按 30 分钟粒度自动对齐）。
2. 提交后在"我的预约"看到状态为"待审核"。
3. 切换到管理员窗口（`admin / Admin@123`）→ "预约审核" → 通过并填写意见。
4. 回到普通用户窗口刷新，看到"已通过"与审核意见。
5. 冲突演示：再次对同一时段提交申请，系统提示"与已有预约冲突（单号）"，说明批准时还会二次校验。

## 3. 知识问答（70 秒，对应 AT-06 / AT-07）

1. 进入"智能助手 → 知识问答"，提问："离心机报 E07 怎么处理？"
2. 指出回答下方列出的引用来源（文档名、片段序号、相关度、原文摘要）。
3. 追问："食堂今天中午吃什么？" 系统明确回答"现有资料无法确认"，不编造结论。
4. 一句话说明：未配置模型 Key 时是降级模式，检索与来源仍然真实，界面有标注。

> 若现场已配置模型 Key，直接展示大模型生成的回答；引用卡片结构一致。

## 4. 智能助手建单（100 秒，对应 AT-09 / AT-10）

1. 切到"智能助手（Agent）"，输入："EQ-002 电镜真空度上不去，帮我报修"。
2. 展开"工具调用轨迹"，指出调用了 `search_equipment` 与 `prepare_repair`，入参与返回都是真实业务数据。
3. 强调："现在只是预览，数据库中还没有工单"。
4. 先点"取消" → 提示已取消，切到"我的报修"确认没有新增记录。
5. 再次发起，点"确认提交" → 返回真实工单号；到"我的报修"看到该工单，来源标记"智能助手"。
6. 说明幂等：重复点击确认不会重复建单。

## 5. 工单处理（60 秒，对应 AT-04）

1. 管理员窗口 → "工单处理"，受理刚创建的工单（状态变为处理中）。
2. 填写处理记录并点"完成"，工单状态变为已完成。
3. 回到用户窗口刷新"我的报修"，看到状态、处理结果与处理轨迹（含操作人、时间）。
4. 顺带说明：对已完成工单再次受理会被拒绝（409），状态机在后端强校验。

## 6. 权限校验（30 秒，对应 AT-05）

1. 用 `student02 / Student@123` 登录（或复用第二个窗口）。
2. 直接访问管理页面 URL（如 `#/admin/repairs`）会被路由拦截回工作台。
3. 说明：即使手工构造请求，后端对 `/admin/**` 与他人记录都返回 403，前端菜单只是引导。

## 7. 收尾（30 秒）

"整个链路是：用户提交 → 后端校验并写库 → 页面可追踪 → 测试可复现。
测试方面我们有 26 项接口用例、4 项 AI 降级演练、16 项浏览器端检查，全部通过，
结果在 `测试结果.xlsx` 和 `evidence/` 目录里，可以现场按编号核对。"

## 常见提问与回答

- **问：AI 答案可靠吗？** 答：回答只基于检索到的片段，并展示来源；资料不足时明确拒绝推断，不替代管理员判断。
- **问：Agent 会不会乱建工单？** 答：Agent 没有写接口，只能生成待确认预览；确认后由后端以当前用户身份建单，且令牌一次性、10 分钟过期。
- **问：并发冲突怎么处理？** 答：提交与批准都对设备行加悲观锁，批准时在锁内二次校验时间冲突。
- **问：为什么用哈希向量？** 答：演示环境无法保证下载句向量模型，哈希向量 + BM25 可离线复现；替换 embedding 模型不影响整体链路。
