## 三、我的设计思路

RAG 链路将知识文档解析、切分、向量化、检索、回答与引用分开处理。检索采用 Chroma 哈希向量与 BM25 词法分数结合，回答附上文档标题和片段编号；资料不足时直接说明无法确认。未配置模型密钥时保留真实检索与来源，回答改为原文摘要并标注降级。

Agent 使用 `search_equipment`、`get_equipment` 和 `prepare_repair` 三个受控工具。报修工具先生成待确认提案，不直接写入工单；用户确认后交由 Java 后端按当前身份建单，取消则不建单。这样把自然语言理解与业务写入权限分开，并保留工具调用轨迹供核查。

## 四、代码实现说明

| 文件或目录 | 职责 | 关键点 |
| --- | --- | --- |
| `src/ai-service/app/rag/` | 文档切分、向量化、存储、混合检索与回答 | 来源引用、证据不足拒答、无模型密钥降级 |
| `src/ai-service/app/agent/runner.py`、`tools.py` | Agent 工具编排 | 查询设备、准备报修、记录调用轨迹 |
| `src/ai-service/app/main.py`、`llm.py` | AI 接口与模型调用 | 与业务后端交互、模型不可用时返回清晰提示 |
| `src/frontend/src/views/AiAssistant.vue`、`Dashboard.vue` | 智能助手与工作台 | 问答引用、待确认卡片、执行轨迹展示 |

在 `RagPipeline.search` 中，系统先从向量库召回候选片段，再计算 BM25 词法分数，按向量 0.45、词法 0.55 的权重排序；`answer` 最多返回 3 条引用。若最佳片段查询词覆盖率低于 0.34 且 BM25 得分不大于 0，则返回“现有资料无法确认”。没有模型密钥或模型调用失败时，仍使用检索到的原文摘要，明确标注降级模式。

在 `agent/runner.py` 中，模型路径最多执行 4 轮工具调用，并记录工具名、入参、返回摘要和成功状态；无模型时采用规则化编排，但仍查询真实设备数据。`prepare_repair` 只产生预览，`AiService.confirm` 才在校验用户、有效期和动作状态后调用报修服务创建工单，重复确认返回原工单结果。

进度跟踪表中，第 1 天计划为启动 AI 服务骨架、准备知识语料并梳理 Agent 流程；第 2 天完成 RAG 检索、引用与拒答的阶段复核；第 3 天完成 Agent 查询、提案和确认/取消的阶段复核；第 4 天验证 AI 异常与降级；第 5 至第 7 天复核模型配置、演示问题与证据归档。
