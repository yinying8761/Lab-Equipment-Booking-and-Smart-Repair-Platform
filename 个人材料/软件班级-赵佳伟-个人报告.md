## 二、我负责的需求

设备预约涉及用户身份、设备状态和时段占用，必须由后端统一校验，避免两个申请同时获批或普通用户查看他人记录。我负责 FR-01~03 的登录、角色与数据归属校验，FR-04~06 的设备查询与管理，FR-07~11 的预约申请、审核和冲突控制；同时承担数据库初始化、后端接口规范及三服务联调。对应验收场景为 AT-01~03、AT-05，并配合 Agent 的后端确认建单链路。

## 三、我的设计思路

后端以 JWT 验证用户身份，并分别校验管理员角色和本人记录归属；AI 服务调用内部工具时另用服务间令牌。设备编号设置唯一约束；预约提交检查时间规则和已批准预约的冲突，管理员批准时在设备行锁内再次校验，使同一设备的并发审核按顺序处理。待审核申请不占用时段，符合课程需求中的审核流程。

数据库脚本建立用户、设备、预约、报修、知识库和 AI 记录等 11 张表及演示数据。启动脚本负责连接 MySQL、Spring Boot、AI 服务和 Vue 前端，便于现场复现。

## 四、代码实现说明

| 文件或目录 | 职责 | 关键点 |
| --- | --- | --- |
| `src/backend/src/main/java/com/labcare/security/`、`service/AuthService.java` | 登录鉴权与权限 | JWT、角色检查、数据归属 |
| `src/backend/src/main/java/com/labcare/service/EquipmentService.java` | 设备台账与管理 | 筛选、详情、状态与编号唯一 |
| `src/backend/src/main/java/com/labcare/service/ReservationService.java` | 预约申请与审核 | 时间规则、冲突检查、设备行锁 |
| `db/init.sql`、`scripts/` | 数据库与集成启动 | 建表种子数据、三服务启动和配置 |
| `src/frontend/src/views/Login.vue`、`admin/AdminEquipment.vue`、`admin/AdminReservations.vue` | 登录与管理页面 | 接口联调与管理操作 |

`AuthInterceptor.preHandle` 解析 Bearer Token，未登录返回 401，普通用户访问管理员接口返回 403；业务服务再按用户 ID 判断记录归属。`ReservationService.create` 先锁定设备，检查可用状态、30 分钟粒度、提前时间、7 天范围及最长 4 小时，再查询已批准预约的时间重叠。`review` 在设备行锁内二次查冲突，保存审核意见、审核人和审核时间；`mine` 只返回本人预约。

`db/init.sql` 建立 11 张业务表、索引和演示数据。启动脚本按配置启动 MySQL 依赖下的 Spring Boot、AI 服务和 Vue 前端。Agent 确认建单由 Java 服务校验用户、令牌有效期和重复确认状态后调用报修服务，AI 工具本身不直接写业务库。

进度跟踪表中，第 1 天计划为初始化 MySQL、启动 Spring Boot 后端并完成登录和设备查询接口；第 2 天复核登录鉴权与权限，第 3 天复核设备和预约主链路，第 4 天完成全量集成；第 5 至第 7 天整理数据库、启动说明、接口测试及提交包检查。
