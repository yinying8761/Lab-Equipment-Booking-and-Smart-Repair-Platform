# 个人报告模板

> 使用方式：复制本文件 → 重命名为 `软件班级-姓名-个人报告.md` → 填写后导出 PDF。
> 建议 2~4 页，重点写“我做了什么、怎么做的、结果如何、在哪里可以核验”。

## 一、基本信息

| 项目 | 内容 |
| --- | --- |
| 姓名 / 学号 | 【姓名】 / 【学号】 |
| 班级 | 【班级】 |
| 组内角色 | 组长 / 组员 |
| 负责模块 | 【例如：后端预约模块】 |

## 二、我负责的需求

说明本人承担的需求编号与内容（引用需求文档编号，如 FR-07~FR-11），以及这些需求对应的验收场景（AT-xx）。

## 三、我的设计思路

- 模块划分与关键类/文件；
- 关键设计决策与取舍（例如为什么把冲突校验放在批准环节、为什么 AI 不直接写库）；
- 与其他模块的接口约定。

## 五、测试与验证

- 本人负责部分的测试用例（编号 + 预期 + 实际结果）；
- 使用的测试方式（自动化脚本 / Postman / 页面操作）；
- 截图或报告位置。

## 六、成果位置

| 类型 | 位置 |
| --- | --- |
| 代码 | `src/...` |
| 文档 | `docs/...` |
